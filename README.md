# Звіт до лабораторної роботи № 2

**Тема:** Глобальні масиви `$_COOKIE`, `$_SESSION`, `$_SERVER`

**Мета:** Ознайомитися з роботою глобальних масивів PHP: `$_COOKIE`, `$_SESSION`, `$_SERVER`. Навчитися використовувати їх для збереження даних між запитами, роботи з сесіями та отримання інформації про сервер.

## Завдання 1. Робота з `$_COOKIE`

**Файл:** `task1_cookie/index.php`

### Опис реалізації
- Форма з одним полем `username` відправляється методом `POST`.
- При відправленні форми виконується:
  ```php
  setcookie('username', $username, time() + 7 * 24 * 60 * 60, '/');
  ```
  Це зберігає ім'я користувача в cookie на **7 днів** (`7 * 24 * 60 * 60` секунд).
- Якщо cookie `username` вже існує (`isset($_COOKIE['username'])`), сторінка одразу виводить привітання без повторного показу форми — це демонструє, що дані **зберігаються між запитами й сеансами браузера**.
- Кнопка «Видалити cookie» надсилає GET-параметр `action=delete`, після чого:
  ```php
  setcookie('username', '', time() - 3600, '/');
  ```
  Термін дії cookie ставиться в минуле, тому браузер видаляє її.

### Ключові моменти
- Cookie зберігається на стороні **клієнта** (у браузері) і надсилається серверу автоматично з кожним запитом.
- `setcookie()` обов'язково потрібно викликати **до** будь-якого виводу HTML (до відкриття тегу `<html>` чи навіть пробілу перед `<?php`).
- Після зміни cookie сторінку перезавантажено через `header('Location: ...')`, оскільки нові значення `$_COOKIE` доступні лише в **наступному** запиті.

## Завдання 2. Робота з `$_SESSION`

**Файли:** `task2_session/index.php`, `task2_session/logout.php`

### Опис реалізації
- На початку кожного скрипта викликається `session_start()` — це ініціалізує або відновлює сесію на основі cookie `PHPSESSID`, яку PHP створює автоматично.
- Форма запитує логін і пароль. Для демонстрації використано «жорстко закодовані» тестові дані (`admin` / `12345`) — у реальному застосунку тут була б перевірка в базі даних із хешуванням пароля (`password_hash`/`password_verify`).
- При успішному вході дані користувача записуються в сесію:
  ```php
  $_SESSION['user'] = [
      'login'      => $_POST['login'],
      'login_time' => date('Y-m-d H:i:s'),
  ];
  ```
- При кожному завантаженні сторінки перевіряється `isset($_SESSION['user'])`: якщо так — виводиться привітання й дані входу, якщо ні — показується форма входу.
- Кнопка «Вихід» відправляє POST-запит на `logout.php`, який:
  1. Очищає масив `$_SESSION`;
  2. Видаляє cookie сесії (`setcookie(session_name(), ...)`);
  3. Викликає `session_destroy()`;
  4. Перенаправляє на `index.php`.

### Ключові моменти
- На відміну від cookie, дані `$_SESSION` зберігаються **на сервері** (у файлі чи сховищі сесій), а клієнту передається лише ідентифікатор сесії.
- Це безпечніше для чутливих даних (наприклад, статусу авторизації), оскільки користувач не може напряму редагувати вміст сесії через браузер.

## Завдання 3. Робота з `$_SERVER`

**Файли:** `task3_server/index.php`, `task3_server/form.php`

### Опис реалізації
Скрипт `index.php` виводить такі дані з масиву `$_SERVER`:

| Параметр | Змінна `$_SERVER` |
|---|---|
| IP-адреса клієнта | `REMOTE_ADDR` |
| Браузер (User-Agent) | `HTTP_USER_AGENT` |
| Назва скрипта, що виконується | `PHP_SELF` |
| Метод запиту | `REQUEST_METHOD` |
| Шлях до файлу на сервері | `SCRIPT_FILENAME` |

### Автоматичне перенаправлення
На початку `index.php` перевіряється метод запиту:
```php
if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    header('Location: form.php');
    exit;
}
```
Якщо запит не є `POST` (наприклад, користувач просто відкрив сторінку через адресний рядок, тобто виконав `GET`), його автоматично перенаправляє на `form.php` — сторінку з формою, кнопка якої надсилає `POST`-запит назад на `index.php`. Лише тоді виводиться таблиця з інформацією про сервер.

### Ключові моменти
- `$_SERVER` — це масив, який **PHP формує сам** на основі заголовків HTTP-запиту та налаштувань веб-сервера; програміст лише читає з нього дані.
- `PHP_SELF` може містити додаткові дані з URL (наприклад, `PATH_INFO`), тому у продакшн-коді його варто екранувати через `htmlspecialchars()` — це зроблено в реалізації.

## Завдання 4. Спільне використання `$_COOKIE` та `$_SESSION`

**Файли:** `task4_cart_cookie_session/*.php`

### Опис реалізації
- `products.php` — статичний «каталог» товарів (масив `id => [name, price]`).
- `add_to_cart.php` — додає обраний товар до `$_SESSION['cart']` (поточний кошик поточного сеансу). Якщо товар вже в кошику — збільшується кількість.
- `clear_cart.php` — очищає `$_SESSION['cart']` без оформлення замовлення.
- `checkout.php` («оформити замовлення») — переносить назви товарів з поточного сесійного кошика в **cookie** `previous_purchases` (у форматі JSON, зберігається 30 днів), після чого очищає сесійний кошик.
- `index.php` — головна сторінка, що показує:
  1. каталог товарів із кнопками «Додати в кошик»;
  2. поточний кошик із `$_SESSION['cart']` (діє лише в межах поточного сеансу браузера);
  3. історію «попередніх покупок» із `$_COOKIE['previous_purchases']` (зберігається навіть після закриття браузера чи завершення сесії, у межах 30 днів).

### Логіка розділення відповідальності
| Що зберігається | Де | Термін дії |
|---|---|---|
| Товари, додані в **поточному** сеансі | `$_SESSION['cart']` | до закриття сесії / браузера |
| Історія **вже оформлених** замовлень | `$_COOKIE['previous_purchases']` | 30 днів, навіть після завершення сесії |

Це наочно демонструє різницю між сесією (тимчасові, серверні дані поточного візиту) та cookie (довгострокові, клієнтські дані, що переживають сесію).

## Завдання 5. Час активності сесії (auto-timeout)

**Файл:** `task5_session_timeout/index.php`

### Опис реалізації
```php
const TIMEOUT_SECONDS = 300; // 5 хвилин

if (isset($_SESSION['last_activity'])) {
    $inactiveFor = time() - $_SESSION['last_activity'];
    if ($inactiveFor > TIMEOUT_SECONDS) {
        $_SESSION = [];
        session_destroy();
        session_start();
        $sessionExpired = true;
    }
}
...
$_SESSION['last_activity'] = time();
```

- При **кожному** завантаженні сторінки скрипт порівнює поточний час (`time()`) з часом, збереженим у `$_SESSION['last_activity']` під час попереднього запиту.
- Якщо різниця перевищує 300 секунд (5 хвилин) — сесія вважається неактивною: масив `$_SESSION` очищується, сесія знищується (`session_destroy()`) і одразу починається нова (`session_start()`), а користувачу показується повідомлення про завершення сесії через неактивність.
- Якщо час не вийшов — `last_activity` оновлюється поточним часом, тобто **лічильник неактивності скидається** при кожній дії користувача (перезавантаженні сторінки).
- На сторінці також є простий JS-таймер (`setInterval`), який візуально показує зворотний відлік — це лише клієнтська індикація, реальна перевірка завжди відбувається на сервері при наступному запиті.

### Ключові моменти
- Такий підхід — стандартний патерн для реалізації **автоматичного logout за неактивністю** (наприклад, у банківських чи корпоративних системах).
- Перевірку варто виконувати на **кожній** сторінці застосунку (найзручніше — виносити в окремий підключний файл `session_check.php`, який підключається на початку кожного скрипта).

## Висновки

У ході виконання лабораторної роботи було на практиці досліджено три ключові глобальні масиви PHP:

1. **`$_COOKIE`** — дозволяє зберігати невеликі обсяги даних на стороні клієнта між різними сеансами браузера (використано для запам'ятовування імені користувача та історії покупок).
2. **`$_SESSION`** — дозволяє зберігати дані на стороні сервера в межах одного сеансу роботи користувача (використано для авторизації та поточного кошика покупок).
3. **`$_SERVER`** — надає інформацію про сервер, скрипт і сам HTTP-запит (IP-адреса, User-Agent, метод запиту тощо), яку часто використовують для логування, аналітики та безпеки.

Також було реалізовано практичний механізм **автоматичного завершення сесії через неактивність**, що є важливим елементом безпеки веб-застосунків, і продемонстровано **спільне** використання cookie та сесій у межах єдиного сценарію (кошик покупок).
